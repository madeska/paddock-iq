# Prospective tree evaluation

No race accuracy result exists yet. docs/prospective-tree/registry.json accounts for each planned2026 R18–23 and currently marks every event pending. Evaluate it with Python scripts/evaluate_prospective_tree.py MANIFEST.json NEW_REPORT.json. Output creation is exclusive. Reports score stored predictions, not newly generated forecasts.

A completed registry event includes round, status=completed, snapshot (local path), publication={runId,commit,path}, outcomes (local path) and outcomesSHA256 (raw file SHA256). Publication path must be under docs/prospective-tree/. The outcome JSON has season, round, raceEndedAt, capturedAt and scores={code,type,actualPoints} entries. Missing actualPoints/null remain missing, while real zero and negative scores are preserved. Pending/excluded events need explicit reasons and remain visible in the report. Exclusions must undergo source review; a registry entry is not exclusion evidence.

Before opening outcome labels, the evaluator verifies frozen snapshot/capture identity, a GitHub server publication receipt, and TypeScript model/prediction parity. It checks the trusted repository, exact workflow-run head commit, server created_at before lock and committed file bytes against the local snapshot. LF-normalized hashing tolerates Git line-ending conversion. Commit author dates, local timestamps, or a claimed URL do not suffice. A workflow need not succeed to prove publication; its failures still matter separately for integration. The current PR workflow can supply the receipt when a committed snapshot triggers a run. If no run exists before lock, this verifier cannot establish eligibility; do not backdate or substitute a later run.

Receipt verification uses read-only public GitHub API calls documented at https://docs.github.com/en/rest/actions/workflow-runs and https://docs.github.com/en/rest/repos/contents . No messages or credentials are sent. A remote publication receipt proves content existed, not official source identity or correct model training provenance.

The report gives paired full per-asset and per-type MAE, RMSE, bias, coverage and a 10,000-draw race-block delta-MAE interval (Random771). Six eligible events are required for the frozen numerical gate. Missing target labels or unforecast outcomes prevent complete coverage. Constructors must remain unchanged. The numerical gate is separate from independent confirmation: every report keeps independentConfirmation=false and activationAllowed=false until the source evidence has been independently audited and reviewed. Source lock, roster, quote timing, feature cutoffs and outcome identity are still unresolved prerequisites. No synthetic test is committed as a race forecast.

Tests: check_tree_publication_receipt.py and check_prospective_tree_evaluation.py. They exercise server time/commit/file binding, missing versus zero outcomes, constructor identity, coverage and insufficient-event gating. Passing synthetic fixtures verify the evaluator, not model accuracy.

Optional source input lineups are preserved as teamNo, five driver codes, two constructor codes and x2, with no profile/email fields. Only these pre-lock snapshot lineups are scored; post-result outcome lineups are ignored. Secondary raw-lineup errors and aggregate MAE/RMSE/bias are reported when all required asset forecasts and labels exist. Chip effects and transfer penalties are excluded, so these are not official account/team totals. No real user lineup has been captured.

The CI workflow now runs the shared/portable TypeScript checks, explicit research script type checks, and dependency-free Python capture/receipt/evaluator guard tests. Pinned sklearn training/export and cross-language capture tests remain separate local checks; guard CI does not silently install a different estimator.
